Environments

Beta to Build Against, and a Flag That Keeps Partners Out of It

Public

The Beta Environment

Build and test on connect2.tsanet.net; production is connect2.tsanet.org. Beta and production behave differently often enough that "which environment" is the first question anyone will ask about a problem. Every call is scoped to your member identity, so GET /v1/me is the cheapest check that your credentials resolve to the company you expect.

Get it a Beta account and credentials from membership@tsanet.org; for OAuth client credentials, TSANet also has to provision your service principal before an app-only token is accepted.

Public

The Test Flag

Create cases with testSubmission: true while you build. It suppresses SLA timers and partner notifications, so nothing you send reaches a real partner's queue. You write testSubmission and read back testCase; that read-back is how you confirm a go-live flip actually happened. Every case that is not test-flagged reaches a real partner.

Get it nothing to install — it is a field on the create request; see collaboration requests.

Reference & Postman

The Endpoint Reference, and the Collection That Exercises It

Public

The API Reference in GitBook

Request and response schemas, parameters and status codes for all 27 paths, generated from the specification. One known drift from the spec is flagged on the API page. The behaviours the reference does not tell you about — the default HTTP 500 error mode, the two note fields, the webhook version trap — are what Working with the API is for.

Get it API Reference · Integration guide · Models

Public

The Postman Collection

Every endpoint as a request you can send against Beta with your own credentials. Send Accept: application/json, application/problem+json on every request, or rejections come back as HTTP 500 with no usable detail.

Get it Postman collection in GitBook. The OpenAPI file the reference and the SDK are generated from is not published; ask membership@tsanet.org for it if you are building a code generator or an agent's tool definitions around it.

SDK & Demo

A Java Client You Can Depend On, and a Demo You Have to Ask For

Public

connect-library

The Java client, generated from the specification and wrapped in nine typed facades. Published to GitHub Packages as a public package at v2.0.0; a token with read:packages is still required to resolve it, even for public artifacts.

Get it Connect SDK → Getting it

Access at onboarding

The Console App

A command per operation — create, approve, reject, information request and response, notes, close, attachments, webhooks — and an optional endpoint that receives webhooks into a local store. The source is public, but the build reads the specification from a private repository, so a clone alone does not build.

Get it a built jar from TSANet at onboarding, or spec access if you need to build it yourself.

Not yet public

The Web Demo

A branded web demo over the SDK facades: dashboard, partner search, the partner's form rendered live, every lifecycle action, webhook management. It is not published as an artifact and there is no hosted instance members can sign into yet. How members get it — a TSANet-hosted instance or a hand-over — is being decided.

Until then ask membership@tsanet.org for a jar or image; if you host it, set TSANET_DEMO_AUTH_PASSWORD or it runs with no auth gate. Runbook on the SDK page.

Test suites

What Proves an Integration Before a Partner Does

Access at onboarding

The Gateway Conformance Harness

For anyone writing an adapter on the Connect Gateway: it drives your real adapter through Connect's failure modes — timeouts, ambiguous submits, duplicate inbound deliveries — and certifies the seam between your code and the engine. Run it continuously from day one, not once at the end.

Get it the conformance module publishes with the gateway at v2.0.0 from the repository's package registry; the repository is private and access comes with adapter onboarding. Details under Building an adapter.

Not yet public

The Connector Test Harness

TSANet's own local harness for testing connectors end to end against the Connect API: contract tests, connector unit suites, and end-to-end drivers for the shipped CRM connectors. It is internal today. Whether members should see it, and in what form, has not been decided.

Until then the Beta environment with test-flagged submissions is the member-facing test bed, and the connector issue trackers are where a failing case goes.
